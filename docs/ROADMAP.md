## M1 — 复盘教练（第一个可用功能）`[ ]`

**场景**：打完一局，在 History 里选它，点"AI 复盘"，得到逐巡讲解：这里切了什么、AI 建议切什么、为什么（结合向听/铳率/和率数字）、有没有更好的路线。

上游已有整局 mjai 事件流（`src/history/`）与 Review 页骨架（现为 MJOT 云端任务、结果跳外部分享页），M1 把闭环搬进应用内并 LLM 化：

- [ ] 后端 `src/tutorial/`：复盘流水线——加载历史对局 → 逐决策点跑 `analysis` + bot 复算 → 生成结构化"讲解原料"（事件 + 数字 + 候选对比）
- [x] LLM provider 抽象（`TutorialProvider` trait）：本地/云端可替换，key 走 config/环境变量，超时 + 失败降级 + 结果缓存（骨架已就绪：`src/tutorial/` 三区 + `[tutorial]` 配置，见 D-0007）
- [x] 参照 bot 就绪：mortal-298k 本地包装入库（`mjai_bot/mortal/`，bot.py 协议代理 + manifest + 对局模拟器；权重与机器配置留在 ignore），作为复盘与候选讲解的"标准答案"参照（见 D-0010）
- [ ] 讲解原料喂给 LLM 生成中文讲解，输出结构化 JSON（分巡、每巡含牌面快照 + 讲解文本 + 关键数字）
- [ ] 前端：History 行内入口 + 应用内复盘渲染页（牌面用现成 `mahgen`；复用 `components/review/` 的骨架）
- [ ] 讲解可对照原始事件流（借鉴 Inspector 的做法），保证 AI 没有胡说

**验收**：选一局真实历史对局，30 秒内得到完整中文复盘；讲解中的每个数字（向听、铳率）来自本地分析引擎而非 LLM 编造；断网/无 key 时功能优雅降级为纯数字复盘。

## M2 — 实时讲解 `[ ]`

**场景**：对局中（或观战时）以可关闭的轻提示解释"AI 为什么这么建议"，把现有 HUD 从"给答案"升级为"给讲解"。双层架构（D-0008）：本地模板为底（即时、免费、离线可用），按需 LLM 深讲（用户主动触发、走 consent 门控）。

详细设计：[docs/design/live-coach.md](design/live-coach.md)。

- [ ] 前端讲解原料装配：订阅现有 `analysis-result` / `bot-response` 事件 + `get_game_snapshot` 快照，模板层零后端改动
- [ ] 模板规则库 v1：五族规则（牌效率进张对比 / 防守安全牌对比 / 立直 vs 默听 / 押受局势 / bot 置信度），条件谓词 + 优先级 + 四语言句式
- [ ] 教练开关（默认关）、节流（每巡至多一条提示、可一键静音到局末）
- [ ] 仪表盘磁贴 `CommentaryTile`（走 `tiles/` 五处登记惯例）
- [ ] 按需 LLM 深讲：IPC 命令复用三区管线（`TurnMaterial` 单巡变体），按 `game_id + 巡目` 缓存

**验收**：默认关闭；开启后模板层无网络依赖、决策点即时出话；深讲走 consent 门控且同一决策点只花一次钱；每巡至多一条提示。

## M3 — 自适应练习系统 `[ ]`

**场景**：零基础到进阶的系统化训练——生成或精选的决策题（14 张牌 + 完整场况），按学员当前水平自适应出题，答完即时判题反馈，可深挖 AI 讲解。题目目的是快速提升水平：甜蜜区难度 + 即时反馈 + 弱点定向。

对比既有形态：比 Mahjong Efficiency Trainer（纯牌效率，无难度体系、无自适应、无解释）多出场况上下文、难度体系、自适应与讲解；比 nagchan 何切練習（人工精选、不可交互、不因人施教）多出交互、判题与因人施教。架构决策见 D-0009。

详细设计：[docs/design/drills.md](design/drills.md)。

- [ ] 题目 schema 与课程表：技能维度（牌效率 / 防守 / 立直与押受 / 副露 / 终局点数）× 难度级，难度由引擎参数定义（候选 margin、向听深度、场况复杂度）
- [ ] 生成管线：约束采样 → analysis 引擎验证 → 答案键（引擎候选排名 + 数字）；精选种子题包（规则/役速查等教学内容并入，引擎复算答案）
- [ ] 学习者模型与自适应选题：per-维度掌握度（EWMA，预留 Elo 演进）、甜蜜区选题（预期正确率 7-8 成）、弱维度加权、错题 spaced requeue
- [ ] 判题与反馈：margin 分级评分（最优/可接受/失误）+ 数字对比反馈 + 可选 LLM 深讲（复用三区）
- [ ] 前端：Tutorial 路由（维度掌握度总览 + 练习播放器）、`tutorialStore`、进度持久化
- [ ] 首批内容：各维度低级别题库 + 牌效率维度"连练到手听"session 模式

**验收**：生成的题 100% 有引擎答案键；无网/无 key 时题库与判题完整可用（仅 LLM 讲解降级）；连续练习能观察到难度随正确率爬升/回落。

## M4 — 个性化学习 `[ ]`

**场景**：实战历史接入 M3 的同一个学习者模型——复盘结论与实战分歧点（学员实际选择 ≠ 引擎最优的决策点）作为模型证据源，弱点检测产出定制题单与课程推荐，学习进度面板可视化。不再另起独立的画像系统。

- [ ] 历史挖掘：从 `src/history/` 提取实战分歧点 → 转为 `mined` 来源的练习题（喂给 M3 题库系统）
- [ ] 弱点检测规则集 → 定制题单 / 课程推荐
- [ ] 学习进度面板（维度掌握度趋势、实战指标变化）

## 非目标（Non-goals）

- ❌ 不开发新的代打（autoplay）能力/引擎（如 MITM 帧注入式代打、新点击自动化）；上游既有 autoplay 引擎可个人复用，fork 侧仅提供对局内开关等便利 UI（D-0011）
- ❌ 不做 LLM 直接决定打牌——决策一律来自可验证的分析引擎/bot，LLM 只负责解释
- ❌ 不做账号体系/云同步（本地优先；LLM 云调用可脱敏 + 可关）
- ❌ 不做完整人机练习对局模拟器——练习系统以决策点题库形态交付（如需重开须新立决策）
- ❌ 不做对局中自动逐巡 LLM 调用——实时讲解的 LLM 层只在用户显式请求时触发（D-0008）

## 风险与对策

| 风险 | 对策 |
|---|---|
| 上游演进导致合并冲突 | fork 改动全部隔离在新目录（见 AGENTS.md §5），定期同步 upstream |
| LLM 幻觉误导学员 | 讲解中所有数字来自本地引擎；LLM 只组织语言；渲染时对照原始数据 |
| LLM 成本与延迟 | 结果缓存、按需生成、provider 可换本地模型；实时讲解模板层零调用（D-0008） |
| 生成题目质量参差 | 引擎验证 + 答案键来自引擎；精选种子题人工把关 |
| 自适应选题冷启动 | 前 N 题按课程表线性推进，学习者模型有数据后切换自适应 |
| 用户隐私（对局数据） | 默认本地存储；上云脱敏且设置可关 |
| 版权/协议（游戏平台 ToS） | 保持上游"仅教育目的"定位，实时教练默认关闭 |
